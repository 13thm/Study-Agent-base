工程化与可观测性 checklist

一个 Demo 和一个生产系统的差距，往往不在模型，而在工程。下面是我在做 Agent 项目时
逐渐攒出来的检查清单。

部署：多阶段 Dockerfile 控制镜像体积；docker compose 一键起全套依赖；非 root 用户
运行；健康检查区分 liveness 和 readiness；优雅关闭要等在途请求跑完。

可观测：结构化 JSON 日志，一个 trace_id 贯穿全链路；指标要包含效果类指标（成功率、
幻觉率、拒答率），不能只有 QPS 和延迟；追踪要能看到每一次 LLM 调用的输入输出与
Token 消耗。

评测：没有评测集的优化等于蒙眼开车。评测集要版本化、要分层、要有负样本和对抗样本。
每次改动都跑一遍回归，重点看"从对变错"的退化案例。

成本：Prompt Caching 要求前缀逐字节一致，把静态内容放最前面；工具返回的长结果必须
剪裁；上下文要有预算，超了按固定顺序降级。这三板斧通常能省下一半以上的开销。

安全：提示注入不可能百分百防住，所以要用最小权限、人工审批、审计日志把损失限制住。
多租户隔离的过滤条件必须下推到存储层，查完再筛是安全事故。
